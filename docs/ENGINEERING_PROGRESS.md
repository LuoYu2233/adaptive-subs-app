## 当前状态

当前阶段：修复可靠性与数据正确性；尚未达到对外商业发布条件。

第一轮已实现：

验证：首轮 24 个 Python 测试、2 个 JavaScript 测试通过；尚未调用真实模型、实测视频平台或 Windows 打包。

第二轮已实现（2026-11-24）：

- 用 SQLite 保存任务快照；重启后在控制台显示待恢复任务。用户触发恢复才继续模型请求。
- 普通字幕按字幕及其相邻上下文、提供商和模型校验，只补缺失批次；启动恢复时不会先覆盖旧快照。
- 取消先停止排队工作，等待已发出的请求完成并保存结果；旧线程退出前禁止重新启动同一任务。
- 同时最多 3 个视频；注释/翻译/释义共享 8 个请求槽位；相同请求合并，避免同时重复生成。
- 客户端关闭隐藏重试，本地缓存或用量日志写入失败不会再次发起已成功的模型请求。
- 任务固定提供商、模型和客户端；生成历史索引及学习档案使用原子写入。
- 控制台与播放器增加取消和继续处理按钮；断线后保留重试入口。

验证：41 个 Python 测试、2 个 JavaScript 测试通过；包含真实工作线程配合模拟模型的取消、重启、上下文失效、并发和磁盘故障测试。所有页面内嵌脚本和独立脚本语法检查通过。

第三轮已实现（2026-11-24）：

- 音频片段按内容、模型、语言和接口地址缓存；恢复时仍需下载/分段，但相同片段不会重复请求识别。
- 语音识别也受全局 8 请求上限约束，且自身最多并发 4 个请求；等待限流时可以取消。
- 识别模型/客户端在任务创建时固定，用量在恢复时延续；快照读取用量受到锁保护。
- 空白响应、本地替代模型缺失或失败都记录为失败；明确的音乐/静音标签仍可以得到有效空字幕。
- 失败的识别片段会结束依赖等待，避免注释工作线程无限等待；不把部分识别结果作为完整缓存返回。

验证：50 个 Python 测试、2 个 JavaScript 测试及全部脚本语法检查通过。新增 9 个语音识别测试使用合成音频和模拟客户端，不发起真实模型请求。

## 每小时复盘

`tools/hourly_review.py` 保存 git 状态、最近提交、离线与浏览器检查结果到 `logs/hourly/`，并使用本机 Codex CLI 把复盘请求排入当前持续任务。
它本身不修改产品代码、不启动额外代理、不公开部署，也不调用付费模型。智能复盘与修复由当前 Codex 任务执行。
执行依赖本机 cron 和 Codex daemon；队列成功不代表复盘已经完成，详见每次报告中的 reminder 结果。

移除调度：`.venv/bin/python tools/install_hourly_review.py --remove`。
临时停用监控：创建 `logs/hourly/PAUSED` 文件。

## 准备环境

使用 Python 3.12。Windows 10 / 11 用于桌面窗口和发布打包；Linux 可运行本地服务与浏览器验证。当前依赖仅已在 Linux / Python 3.12 验证，Windows 发布前须独立验证打包产物。

```bat
git clone https://github.com/LuoYu2233/adaptive-subs-app.git
cd adaptive-subs-app
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

API key：把 `.env.example` 复制成 `.env` 填进去，或者启动后在设置页里填（从源码运行时设置页写的就是这个 `.env`）。
`.env` 已经在 `.gitignore` 里，不要提交。

`requirements.txt` 固定直接依赖和英语分析模型版本；更新依赖后先跑 `python -m pip check` 和离线检查。

离线回归：安装 `requirements-test.txt` 和 Node.js 22，再运行 `python tools/quality_check.py`。
完整浏览器检查：安装 `requirements-browser.txt`，运行 `python -m playwright install chromium`，再运行 `python tools/browser_check.py`。
浏览器检查使用临时用户目录并清除测试进程中的 API key，不调用真实模型，截图和日志位于 `test-results/browser/`。
Linux 缺少浏览器系统库时，使用 `python -m playwright install --with-deps chromium` 安装。

学习规则和画像写入队列的源文件是 `shared/learning.js`、`shared/profile-sync.js`。修改后运行 `python tools/sync_assets.py`，同步到网页和插件；离线检查会核对两个副本。
旧版词条标记继续生效，新版带上下文释义的标记使用独立义项键，精确标记优先。释义文字改写可能产生新键，避免把不确定的不同意思合并。

## 目录结构

```
app/                      本地程序
  main.py                 程序入口：装好日志，再以窗口模式启动 server
  server.py               本地 HTTP 服务器：页面、/api/*、注释任务、语音识别任务、程序窗口
  annotate.py             注释流水线：spaCy 分词 + 词频筛选 + 大模型结合上下文注释、缓存
  providers.py            注释模型配置（OpenAI / DeepSeek / 小米 MiMo）
  asr.py                  音频分段并行下载（B 站 / YouTube）、边下边切句、MiMo ASR、标签清理
  local_asr.py            本地 Whisper（faster-whisper base.en，int8，CPU）：补识别被接口拒绝的句子
  profile_store.py        英语画像、熟词库、单词标记、词典释义
  applog.py               把输出同时写进日志文件和控制台面板（打包后没有命令行窗口）
  web/                    程序里的网页
    app.html              控制台（程序窗口）和入场动画
    setup.html            API key 和模型设置
    profile.html          英语画像和词汇测试
    player.html           YouTube 播放器
    assets/               脚本、样式、图标、入场插画
  data/
    exam_words.json       考试词表和简短释义（由 tools/make_exam_words.py 从 ECDICT 生成）
    vocab_test.json       词汇测试题库（由 tools/make_vocab_test.py 生成）
    ranks_en.txt          英文词频排名（不提交，打包时自动生成）
  models/                 本地语音识别模型（不提交，打包时自动下载）
extension/                Chrome / Edge 插件（Manifest V3）
  content.js              运行在 B 站和 YouTube 的视频页：取字幕、显示注释、点词卡片、遮挡板、拖动
  background.js           和本地程序通信（网页不能访问 127.0.0.1，插件可以）
  popup.html / popup.js   工具栏弹窗
packaging/
  build.py                原生 Windows 打包：生成带版本号的 Windows ZIP 与校验文件
  AdaptiveSubs.spec       PyInstaller 配置
tools/                    一次性脚本：生成数据、图标、在线演示
  art/mascot.jpg          图标原图
docs/                     使用指南、开发说明、README 用的截图
start.bat                 从源码启动（需要先建好 .venv）
```

运行时生成、不提交的东西：`.env`、`profile.json`、`.cache/`（API 结果缓存和用量记录）、`data/`（处理过的视频）、
`logs/`、`build/`、`release/`、`site/`。

## 从源码运行

```bat
start.bat                                  # 和程序一样：窗口 + 控制台
.venv\Scripts\python app\main.py           # 同上
.venv\Scripts\python app\server.py --open  # 只启动服务器，在浏览器打开 YouTube 播放器
```

- 从源码运行时，设置、画像、处理过的视频、缓存和日志都在仓库根目录；打包后的程序放在 `%LOCALAPPDATA%\AdaptiveSubs`
- 默认端口 8765，被占用时顺延；`--port` 可以指定
- 改了插件文件：在 `chrome://extensions` 里点 Adaptive Subs 的刷新按钮，再刷新视频页面

环境变量：

| 变量 | 作用 |
|---|---|
| `ASUBS_HOME` | 换一个数据文件夹（测试时不碰自己的画像和视频） |
| `ASUBS_HEADLESS=1` | 不开窗口，只运行服务器（自动化测试用） |
| `ANNOTATION_PROVIDER` | `openai` / `deepseek` / `mimo` |
| `OPENAI_MODEL` | 换 OpenAI 模型 |
| `DEEPSEEK_MODEL`、`MIMO_MODEL` | 换对应服务商的注释模型，也可从设置页修改 |
| `MIMO_BASE_URL`、`ASR_MODEL`、`ASR_RPM` | 语音识别接口、模型、每分钟请求上限（默认 90） |

### 命令行批量处理（可选）

不开网页也能处理整集，结果和播放器通用：

```bat
.venv\Scripts\yt-dlp --skip-download --write-subs --sub-langs en --sub-format srt -o "data/%(id)s.%(ext)s" "https://www.youtube.com/watch?v=视频ID"
.venv\Scripts\python app\annotate.py data\视频ID.en.srt --title "视频标题"
```

- `--dry-run`：只跑词频筛选，不调用 API
- `--export-srt 5000`：从已有 JSON 导出带括号注释的 `.srt`，供支持 SRT 的播放器使用，不请求模型。仅按选定词汇量筛选，每个义项最多提示 2 次、每句最多 3 个，不包含画像中的个人标记。不同意思分别计数；无效参数、损坏或不完整结果不会覆盖原有导出文件。

API 结果缓存在 `.cache/`，相同模型、接口和输入的有效结果可以复用。切换配置、修改原句、缓存缺失或校验失败时，重新生成可能产生新的模型用量。

## 它是怎么工作的

**注释**（`annotate.py`）：

1. spaCy 分词、词形还原，按词频给每个词一个难度；按考试词表校准（课本少教的生活词汇算得更难）
2. 字幕每 12 行一批发给大模型，带上前后文，让它标出单词、短语 / 习语、熟词僻义，每条带难度值和简短中文
3. 显示时再按学习者的熟词库和标记筛选，所以换词汇量、改标记不用重新调用模型
4. 离观看位置近的批次优先、低思考强度；拖动进度条后优先处理跳到的位置

**语音识别**（`asr.py`、`local_asr.py`）：

- B 站 CDN 对每个连接只给开头约 3 MB 的全速，之后约 140 KB/s。所以按 1 MB 分段、8 个连接并行下载到内存
  （开头 4 段用 256 KB，第一句出来得更快），PyAV 一边读一边解码
- `StreamSegmenter` 按停顿把音频切成 2–7 秒的句子，每 60 秒切一次、留 6 秒尾巴等下一段接上
- 每句发给 MiMo ASR；`finish_reason == "content_filter"` 或返回拒绝文字时，改用本地 Whisper 识别这一句
- 去掉 `<chinese>`、`[Music]`、`(applause)`、`♪` 这类标签

**英语画像**（`profile_store.py`、`web/assets/profile.js`）：

- 考试成绩对应考试词表和先验水平；词汇测试两阶段自适应（先粗测 9 个词频段，再在分界附近细测），保序回归平滑
- 熟词库 = 考试词表中排名靠前的词 + 高频词 + 测试中认识的词，再按标记增减。短语和熟词僻义不受熟词库影响

**插件**：`content.js` 用用户已登录的身份读取 B 站字幕列表，`background.js` 把字幕和视频编号交给本地程序，
注释结果通过事件流（`/api/ext/events`）逐批推回来。

## 打包成 Windows 程序

```bat
.venv\Scripts\python -m pip install -r requirements-build.txt
.venv\Scripts\python packaging\build.py
```

需要 Windows、Git 和 Python 3.12 的独立环境。先提交并检查改动；脚本拒绝脏工作区，只从已提交的允许路径创建临时源码目录。
生成 `release/AdaptiveSubs-<版本>-Windows.zip` 和 `.zip.sha256`，包含 `程序/`、`浏览器插件/`、`使用说明.txt` 和 `RELEASE-MANIFEST.json`。
清单记录版本、提交、构建环境依赖版本及逐文件 SHA-256；文件校验通过后才创建最终 ZIP，已有同版本不同内容会报错，旧包保留。

- 构建工具固定为 [PyInstaller 6.22.3](https://pypi.org/project/pyinstaller/6.22.3/)。[PyInstaller 需要在目标系统构建](https://pyinstaller.org/en/stable/)，此流程不能在 Linux 生成 Windows EXE。
- 本地已有语音模型时只复制固定清单中的文件并重新校验；没有时在临时目录下载约 148 MB 的固定版本。不同或损坏的本地模型会导致构建失败，不会静默替换；不再使用未经清单校验的量化模型。
- 英语词频表在临时目录重新生成，不使用本机旧表；插件从提交中读取，不复制工作目录里的忽略文件；PyInstaller 输出也来自本次新建目录。
- 清单与校验值只能检查内容完整性，不能替代签名、原生运行验证或组件授权审查。原生输出不保证跨环境逐字节一致。
- 此次只在 Linux 验证了制包边界与合成二进制测试，未生成或验收 Windows 可执行程序。

校验解压前的 Windows ZIP：

```bat
.venv\Scripts\python packaging\verify_windows_release.py release\AdaptiveSubs-<版本>-Windows.zip
```

打包后不弹窗口的冒烟测试：

```bat
set ASUBS_HEADLESS=1
set ASUBS_HOME=%TEMP%\asubs-test
程序\AdaptiveSubs.exe --port 8790
```

在解压后的目录运行以上命令，访问 `http://127.0.0.1:8790/app`、`/api/status`（需要请求头 `X-Adaptive-Subs: 1`），检查版本、`local_asr` 和本地组件状态；之后还需验证真实窗口、插件及退出。

## 发布新版本

1. 同步 `app/version.py` 与 `extension/manifest.json` 的版本号，更新 `docs/RELEASE.md`，完成检查并提交。
2. 在 Windows 使用 `packaging\build.py` 构建，校验 ZIP，解压后执行冒烟测试，再实际装上插件验证平台和真实模型行为。
3. 另行完成签名、授权与商业发行验收，再决定公开发布。当前自动工程任务只生成本地试用源码包，不自动推送或发布 Releases。

## 安全约定

- 设置写入采用编辑版本：先 GET `/api/settings` 取得 `rev`，POST 同一路径时携带 `expected_rev`。成功保存后使用响应 `settings.rev`；409 表示未写入，应重新读取并核对，不自动重试旧请求。版本在成功写入和进程重启后改变，不能用作身份认证。

- 画像表单、词汇测试、批量重置：先 GET `/api/profile`，提交身份、专业、成绩、测试或 `reset_marks` 时携带读取到的 `expected_rev`。校验与写入在同一把锁内，409 不会修改画像。网页分别保留表单加载时和测试开始时的版本；概览刷新不会让旧表单自动取得新版本。逐词 `/api/mark` 以及旧版只提交 `level` 的单字段请求仍可使用；它们会改变画像版本，也可能使旧表单过期。冲突时先核对，再由用户主动重新保存，不自动合并覆盖。升级后应刷新所有已打开的画像页面。

- 服务器只监听 `127.0.0.1`，并检查 `Host` 头，防 DNS 重绑定
- 除了页面和 `/api/health`，所有 `/api/*` 接口都只接受带 `X-Adaptive-Subs: 1` 请求头的请求。
  网页没法跨站带上这个头，所以别的网站不能借本地程序花用户的 API 额度、读画像或改设置
- 语音识别只接受 BV 号或 YouTube 视频 ID，由服务器自己拼出视频地址，不会下载任意网址
- 用户的 B 站 / YouTube Cookie 不离开浏览器；发给本地程序的只有字幕文字和视频编号（YouTube 只有视频编号）
- 插件不给 innerHTML 赋值：YouTube 页面启用了 Trusted Types，赋值会直接报错。界面一律用 DOM 方法拼
- 不要提交 `.env`、`profile.json`、`data/`（别人视频的内容）

# 竞品调研：WordGlance｜生词字幕

> 调研日期：2026-11-19 · 官网 <https://wordglance.com/>
> 信息来源：官网各页面（亲自走了一遍词汇测试）、数据来源页、Firefox / Edge 商店页。Chrome 商店页在调研用的浏览器里打不开，用户数未知。

---

## 1. 一句话概括

和我们的想法**几乎一模一样**："保留完整英文字幕，只给不认识的词添加中文提示"。区别在于实现方式：

- 免费版**完全基于本地词典**：按 CEFR 等级判断难度，释义默认取词典第一个意思
- 结合语境理解词义、解释习语这类 AI 能力，被规划成**"即将上线"的付费功能**

## 2. 基本情况

| 项目 | 情况 |
|---|---|
| 上线时间 | 约 2026 年 10 月（数据下载于 10-10；Edge 最早评价 10-25；Firefox 首发 11-07） |
| 当前版本 | v0.10.x，自称"原型" |
| 平台 | Edge / Chrome / Firefox 电脑端插件，外加一个学习中心网站 |
| 用户量 | Edge 18 个用户，4 条评价，均为 5 星；Firefox 1 个用户，0 评价；Chrome 未知 |
| 价格 | 免费；AI 辅助版计划收费，尚未开放 |
| 团队 | 推测是个人或小团队（隐私政策托管在 `chatgpt.site` 子域名下，开源许可为 MIT） |
| 安装包 | Firefox 版 **120 MB**，因为整套 ECDICT 词典打包进了插件 |

**判断**：产品打磨得相当细，但还处于非常早期，几乎没有用户。

## 3. 功能清单

### 3.1 字幕注释（核心）
- 读取网页播放器的英文文字字幕轨，在生词后面用括号加中文，例如 `admit（承认）`、`freaked out（吓坏了）`
- 提示等级按 **A1–C2** 六档设置：选 B1，就只注释高于 B1 的词
- 字幕框可以拖动，盖住原字幕，位置会被记住；控制按钮只在鼠标悬停时出现
- **画面字幕识别（测试功能）**：对烧录在画面里的字幕做本机 OCR，已在部分 B 站视频上验证，可能有误字或延迟
- 支持简体 / 繁體切换
- 视频没有英文字幕时不能用，不做语音识别

### 3.2 点词交互
- 点击没有注释的词：查词典，并标记"不认识"，同时保存当前例句
- 点击已有注释的词：标记"认识"，以后不再提示；Shift + 点击可以标记"不认识"
- 本地完整词典（ECDICT，340 万条记录），查词不需要联网

### 3.3 学习中心（网站）
- 生词本：单词、短语、已掌握分栏显示，可查看英文解释、完整释义和收藏的原句
- 每日复习：每轮 10 或 20 个
- 不登录时数据存在本机；登录后跨设备同步；支持导出、导入备份

### 3.4 词汇测试（可选，2–4 分钟）
我亲自走了一遍：

1. A1–C2 每档 1 组，**每组 8 个词，共 48 个**
2. 每个词三个选项：认识 / **不确定** / 不认识
3. 最后一步**核对词义**：从你选了"认识"的词里抽 3 个，给一个例句，从 4 个中文意思里选（例如 `We were fortunate to find a seat.` → 幸运的）
4. 结果给出建议等级（如 A2）、每档答对数，以及一个**估计词条范围**（我这次是 2,700–5,100）
5. 页面上写明：测试未经标准化验证，可参考 LexTALE

### 3.5 官网演示
- 用一段真实电影片段，**左右同步播放**"WordGlance 字幕"和"普通英文字幕"做对比
- 演示里可以"随便点击一个陌生的词"模拟查词
- 可以上传本地视频试用

## 4. 做得好的地方

1. **演示很直观**：真实片段左右对比，再加上可以点词，用户几秒钟就明白产品在做什么。
2. **词汇测试体验友好**：
   - 有"不确定"选项，降低用户压力
   - 用"核对词义"代替假词来防止虚报，用户感觉是在做题，不像在被抓作弊
   - 结果附带"测试怎么判断？"的说明，很透明
3. **学习闭环完整**：看剧 → 点词 → 收藏原句 → 复习，并且"已认识的词下次不再提示"。字幕上一次点击就能标记认识或不认识，操作成本很低。
4. **适用范围广**：不绑定特定网站，只要能读到字幕轨就能用；还有 OCR 兜底来处理烧录字幕。
5. **免费、离线、不强制注册**，隐私友好。
6. **数据来源透明**：专门有一页写清了词表、词典的出处、许可和局限。
7. **细节到位**：繁简切换、字幕框拖动、悬停才出现控件、手机端引导用户去电脑安装。

## 5. 做得不好或有局限的地方

1. **不懂语境，这是最大的短板**
   - 释义"默认取常见首义"，只有约 58 组人工写的正则搭配规则来选择语境义。他们自己也写了：未覆盖的、冲突的、隐喻和语气依赖的用法"仍可选错"
   - 一词多义翻错是必然的（比如 `upset the order` 很可能被注成"难过"）
2. **熟词僻义是结构性盲区**：难度按词的**最低 CEFR 等级**算，所以 `upset`、`address`（处理）、`compute`（算力）这类常见词的少见义项，**永远不会被标出来**。
3. **习语覆盖有限**：短语靠人工词条，精选库一共 864 条，日常对白里的习语和俚语大量漏掉。这部分被留给了付费的 AI 版。
4. **用户水平模型太粗**：
   - 只有 6 档，A2 和 B1 之间差了一大截
   - 48 个词的测试，估计范围宽达 2,700–5,100 词
   - 词义核对只抽 3 题，而且抽到的都是低档的简单词（fortunate、doctor、journey），高档词虚报几乎抓不到
5. **括号注释会加长字幕行**：中文跟在单词后面，整行变长容易换行，读起来有点断断续续。
6. **安装包 120 MB**：对浏览器插件来说很重，安装和更新都慢。
7. **只支持电脑**，没有字幕的视频不能用，也不做语音识别。
8. **几乎没有用户**，产品方向还没有被市场验证。

## 6. 可以借鉴的地方

| 借鉴点 | 放到我们的哪一步 |
|---|---|
| 官网**左右对比演示** + 点词试用 | GitHub Pages 演示页：加一个"纯英文 vs 自适应"的并排模式 |
| 测试里的**"不确定"选项** | Phase 1 词汇测试 |
| **核对词义**（例句选择题）防虚报，和我们计划的假词**一起用**，并且**从高档词里抽题** | Phase 1 词汇测试 |
| 字幕上**一次点击标记认识/不认识** | 播放器加点词交互（Phase 4 个人词库） |
| 收藏单词时**连同原句一起保存** | 生词本导出 |
| 繁简切换、字幕框拖动、控件悬停才出现 | 做插件时再考虑 |
| 数据来源和许可说明页 | 以后对外发布时补上 |

## 7. 我们可以做得更好的地方（差异化）

1. **把"结合语境"做成核心，而且免费**
   - 他们把语境理解当付费功能，"即将上线"；我们的 demo 已经能做到：`compute` 翻成算力，`get this right` 翻成做对，还能识别 `turned out to be`、`at the heart of`、`close the gap between` 这类短语
   - 熟词僻义也是他们结构上做不到、而我们天然能处理的
2. **更细的用户水平模型**
   - 用"词频排名 → 认识概率"曲线，代替 6 个 CEFR 档位
   - 用户每次标记"认识/不认识"都实时修正这条曲线
3. **控制注释密度**
   - 我们已经做了：每个词最多标 2 次，并且统一用第一次的译法
   - 还可以再加：每行最多标 N 个，优先保留最难的
   - 目标是把整集平均控制在每句 0.5–1 个注释
4. **"上方小字"显示**：中文放在单词上方，不改变字幕行长度，比括号更不打断阅读。
5. **利用"整集预处理"的优势**（他们是逐句处理，做不到）：
   - **看前预习**：本集最关键的 10–20 个生词
   - **看后复习**：生词卡片上带时间戳，点一下就跳回原片段，**重听原声**
6. **成本可控**：按"视频 + 档位"缓存，同一集同一档位只算一次，所有用户共享。热门剧集可以提前算好。
7. **补上他们不做的能力**：没有字幕的视频用语音识别（如 Whisper）生成字幕；可以考虑做手机或平板可用的网页播放器。

## 8. 风险与应对

- **他们起步更早**：三个商店都已上架，体验打磨得也细，而且已经预告了 AI 版。我们的差异化窗口可能不长。
  - 应对：尽快把"语境注释质量"这个最强的点做扎实，并用数据证明（漏标率、误标率、和词典方案对比）。
- **LLM 有成本，他们的免费版是零成本**。
  - 应对：共享缓存 + 小模型 + 只翻生词，把每集成本压到几分钱。
- **同质化**：口号几乎一样，用户分不清。
  - 应对：对外宣传主打"懂语境、懂习语、标注量刚刚好"，演示时专门挑一词多义和习语多的片段，和词典方案并排对比。
